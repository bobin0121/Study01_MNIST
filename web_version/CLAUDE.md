# CLAUDE.md — 웹 버전

브라우저에서 손글씨 숫자를 인식한다. 학습된 CNN의 순전파를 자바스크립트로
직접 구현했다.

## 절대 규칙

**외부 라이브러리를 쓰지 않는다.** ONNX Runtime, TensorFlow.js, npm 패키지,
번들러, CDN 스크립트 모두 금지다. 브라우저 내장 기능(ES Modules, Canvas 2D,
fetch)만 쓴다. 빌드 단계도 없다 — GitHub Pages가 이 폴더를 그대로 서빙하면
동작해야 한다.

전체 연산량은 약 420만 MAC이라 프레임워크 없이도 즉시 끝난다.

## 실행

`.bin`을 `fetch`로 읽기 때문에 `index.html`을 파일로 직접 열면(`file://`)
동작하지 않는다. 서버를 띄운다.

```
cd web_version
python -m http.server 8000
```

- `http://localhost:8000/` — 앱
- `http://localhost:8000/검증.html` — 검증 페이지

검증 페이지는 `검증데이터.json`이 필요하다. 이 파일은 깃에 없으므로
먼저 만들어야 한다.

```
cd desktop_version
python 검증데이터만들기.py
```

## 배포

**GitHub Actions 방식으로 이 폴더만 사이트 루트에 올린다.**
주소는 다음과 같다.

```
https://<사용자>.github.io/Study01_MNIST/
```

브랜치 배포(Deploy from a branch)를 쓰지 **않는** 이유는, 그 방식은 소스
폴더로 루트 또는 `/docs`만 고를 수 있기 때문이다. 이 저장소는 루트에
`index.html`이 없고 `web_version/` 안에 있어서, 루트 배포를 쓰면 주소가
`.../Study01_MNIST/web_version/`으로 길어진다.

배포는 `.github/workflows/pages.yml`이 담당하며, `master`에 푸시할 때마다
`web_version/` 안쪽만 올린다. 빌드 단계는 여전히 없다 — 워크플로는 파일을
그대로 올리기만 한다. 모든 경로가 상대 경로라 사이트 루트가 바뀌어도
그대로 동작한다.

현재 설정을 확인하려면:

```
gh api repos/<사용자>/Study01_MNIST/pages --jq '{build_type, html_url}'
```

`build_type`이 `workflow`여야 한다. `legacy`로 나오면 아직 브랜치 방식이라
주소가 달라진다.

`검증.html`은 픽스처가 깃에 없어 배포본에서 동작하지 않는다. 검증 페이지는
개발 도구이지 배포 대상이 아니다.

## 파일별 책임

- `연산.js` — 레이어 연산만. `conv2d`(3x3, stride 1, padding 1 고정),
  `relu`(제자리), `maxPool2d`(2x2, stride 2 고정), `linear`, `softmax`.
  모두 순수 함수이고 모델을 알지 못한다. 드롭아웃은 예측 시 항등이라 없다.
- `모델.js` — `loadModel(basePath)`이 매니페스트와 `.bin`을 읽어
  `Float32Array` 뷰를 자르고, `predict(입력784개)`가 `model.py`의 `forward`와
  같은 순서로 순전파한다.
- `전처리.js` — 280x280 그림을 정규화된 28x28로 바꾼다.
  **정규화 상수를 이 파일에 적지 않는다.** `가중치정보.json`에서 읽어 인자로 받는다.
- `그림판.js` — 캔버스 그리기만. 추론을 알지 못한다.
- `앱.js` — 위 셋을 연결하고 화면을 갱신한다.
- `index.html`, `스타일.css` — 앱 화면. `검증.html`은 검증 전용이며 별도 스타일을 자체 포함한다.

## 가중치 형식

`desktop_version/가중치내보내기.py`가 만든다. 직접 고치지 않는다.

- `가중치.bin` — Float32 리틀엔디안, 텐서 8개를 고정 순서로 이어붙임.
  421,642개 값, 1,686,568 바이트.
- `가중치정보.json` — 텐서별 이름/shape/바이트 오프셋/개수, 그리고 정규화
  상수 `mean`/`std`. 오프셋은 항상 4의 배수다
  (`new Float32Array(buffer, offset, count)` 요구사항).

## 전처리

MNIST 원본 데이터의 생성 방식을 따른다.

1. 그려진 픽셀의 경계상자를 자른다 (비어 있으면 안내 메시지)
2. 비율을 유지한 채 긴 변이 20px가 되도록 면적 평균 축소
3. 잉크의 무게중심이 28x28 중앙에 오도록 정수 평행이동
4. `/255` 후 `(x - mean) / std`

반올림은 `파이썬반올림()`을 쓴다. 자바스크립트 기본 반올림은 .5를 항상 올리지만
파이썬 `round`는 은행반올림이라 .5를 짝수 쪽으로 보낸다. 이 파일은
`검증데이터만들기.py`의 전처리를 그대로 옮긴 것이므로 그 규칙까지 맞춘다.

축소는 PIL의 LANCZOS 대신 면적 평균을 직접 구현했다. 브라우저에서 LANCZOS를
그대로 재현할 수 없기 때문이며, 정확도가 기준을 넘어 Lanczos는 구현하지 않았다.

`desktop_version/predict_gui.py`는 이 보정을 하지 않는다. 같은 그림에 두 버전이
다른 답을 낼 수 있다.

펜 굵기는 캔버스 픽셀 기준 18px로 고정되어 있다(`그림판.js`의 `펜굵기`).
숫자를 크게(세로 200px 안팎) 그리면 MNIST의 획 굵기 비율(긴 변 대비 약 0.1)에
가깝지만, 작게(세로 60px 안팎) 그리면 그 비율이 0.3에 가까워져 20px 상자에
맞춘 뒤 뭉툭한 덩어리가 될 수 있다. `index.html`이 "크게 그리라"고 안내하는
것은 이 한계를 완화하기 위해서이며, 알려진 한계로 남겨둔다.

## 측정 결과

`검증.html`로 MNIST 테스트 200장에 대해 측정한 값이다.

| 항목 | 기준 | 실측 |
|---|---|---|
| 순전파 일치 (확률 최대 절대차) | ≤ 1e-4 | 2.41e-7 |
| 전체 정확도 | ≥ 97% | 98.0% (196/200) |
| 전처리 최대 오차 | 참고용 (기준 없음) | 5.75e-7 |

모델 구조나 가중치를 바꾸면 다시 측정해 이 표를 갱신한다.

전처리 최대 오차는 하드 기준이 아니라 참고 지표다. 파이썬(`검증데이터만들기.py`)과
브라우저(`전처리.js`)의 리샘플링 구현은 애초에 픽셀 단위로 같지 않게
설계되어 있다. 다만 이 값이 지금 자릿수(1e-7대)에서 갑자기 몇 자릿수 뛴다면,
그것은 두 구현의 전처리가 서로 어긋나기 시작했다는 신호이므로 정확도 수치를
믿기 전에 먼저 원인을 맞춰봐야 한다.

전체 정확도 98.0%는 MNIST 테스트 이미지를 10배 최근접 확대(nearest-neighbour)한
입력으로 측정한 값이다. 이 이미지들은 이미 LeCun의 전처리로 20x20 경계상자에
맞춰지고 무게중심이 중앙에 오도록 정리되어 있어, 10배 확대해도 경계가 또렷하고
획 굵기가 일정하며 이미 중앙에 놓여 있다. 즉 이 측정은 `preprocess()`가 구제해야
할 "제멋대로인 입력"을 사실상 거치지 않는다. 실제 손그림은 안티앨리어싱이
섞여 있고 위치와 크기가 제각각이므로, 이 98.0%가 사용자의 손글씨 인식률을
예측하지는 않는다.
